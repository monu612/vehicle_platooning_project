## 2024-03-21 - Optimization of max/min in tight loops
**Learning:** In highly optimized Python code, built-in function calls like `min()` and `max()` introduce measurable overhead when executed heavily in tight loops (e.g., across many edges in a graph in every simulation iteration). Replacing these with equivalent inline conditional constructs (such as ternary operators `A if A > B else B` or simple `if/elif/else` blocks) inside helper functions effectively reduces this overhead while avoiding the cluttering of the caller's scope with boilerplate code.
**Action:** When identifying bottlenecks in functions executing thousands of times per second (like `_edge_metric` in ACO path scoring), consider converting simple `min()`/`max()` bounds checks to inline conditionals, especially if automated reviews reject larger structural changes or inlining in the caller.
