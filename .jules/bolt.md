## 2024-05-24 - Pre-computing Paths Instead of Dynamic Traversal in Simulation Loop
**Learning:** In the dynamic routing simulation, calling `nx.all_simple_paths` repeatedly inside the per-iteration loop (which generates paths lazily) is a major performance bottleneck due to the sheer number of generator iterations per destination when simulating across many runs. Caching generator-based algorithms onto the dynamic graph directly is unsafe due to mutation, but since the simulation loop only *removes* edges or adjusts weights from a static base topology, the base paths are strictly bounded.
**Action:** Always pre-compute structural attributes like all simple paths once based on the pristine static topology before entering high-frequency loops. In the inner loop, dynamically filter out invalid precomputed paths by checking if the consecutive edges still exist (`G.has_edge(u, v)`). This avoids heavy pathfinding overhead during the simulation.
