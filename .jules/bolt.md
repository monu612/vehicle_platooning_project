## 2023-10-01 - Python function call overhead in tight numerical loops

**Learning:** In CPython, invoking a built-in mathematical function like `min()` or `max()` inside extremely tight numerical loops (such as those iterating over edges and evaluating metrics thousands of times in Ant Colony Optimization pathfinding) incurs notable bytecode `CALL_FUNCTION` overhead compared to native operations. Relying heavily on these built-ins for basic bounds checking or threshold clamping severely bottlenecks execution speed.
**Action:** Replace `min()` and `max()` calls with inline `if`/`else` conditional branches or ternaries when performing simple threshold clamping inside hot paths. While slightly less idiomatic, avoiding the function call overhead yields significant throughput gains (e.g., 60-80% faster execution per iteration) without fundamentally changing logic or readability. Ensure explicit comments are left justifying the unidiomatic micro-optimization to reviewers.
