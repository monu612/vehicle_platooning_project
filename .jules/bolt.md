## 2026-09-16 - [Replace max/min with inline ternary]
**Learning:** Python's built-in `min()` and `max()` functions have surprising overhead when called millions of times in tight loops like `_path_score`. While inlining the whole dictionary access into `_path_score` works, it leads to unreadable boilerplate. Optimizing the internal logic of the generic wrapper functions themselves (e.g. replacing `max()` with a simple ternary `value if value > MIN_EDGE_COST else MIN_EDGE_COST`) is significantly cleaner and still yields a ~3x performance gain in those wrapper functions, avoiding code rejection while retaining the speed up.
**Action:** Replace `min()` and `max()` with inline ternaries inside heavily called wrapper functions instead of fully inlining the wrapper logic into the caller.
